# Combat AI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A strong, rule-abiding combat "brain" plus a Node fight-simulation runner that reports win rates, first KOs and rule violations.

**Architecture:** The brain looks ahead by running candidate turns through the **real engine** (`js/combat-logic.js`) on snapshots of the global state `S`, sampling dice from its own random stream and scoring the result; a successive-halving search spends a fixed simulation count (runner) or a wall-clock budget capped at 8 s (browser later). The engine gains only: an injectable random source, a headless mode (no timers, no page), snapshot/restore, and one extracted teleport function. The runner and rule checker live in `tools/` and are development-only.

**Tech Stack:** Vanilla JS ES modules, Node 24 (`node:test`, `node:assert/strict`), no dependencies.

**Spec:** `docs/superpowers/specs/2026-10-28-combat-ai-design.md`

## Global Constraints

- No frameworks, no dependencies, vanilla JS in ES modules; the site must not need `tools/` or any `package.json` at runtime.
- The deployed site stays a static site on Vercel's free plan: the brain runs client-side (browser) or in plain Node; no server, no network calls.
- A decision may **never take more than 8 seconds** (hard cap, wall-clock mode); the runner uses a **fixed simulation count** so the same seed replays identically; a 50-fight batch at the default budget takes **about 20 minutes**.
- The brain acts only through the engine's own handlers (`handleAttack`, `handleCastAbility`, `handleMoveClick`, `handleActivateDomain`, `handleTransform`, `handleReactYes`/`handleReactNo`, `handlePass`, and the extracted teleport function). No copy of the rules.
- The brain never sees the real fight's upcoming dice: lookahead uses a separate random stream.
- All 28 existing tests keep passing and `combat.html` behaves exactly as before (verify by running `node --test tests/*.test.mjs`).
- Run tests with `node --test tests/*.test.mjs` (a bare directory argument fails on this Node).
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

- Uneven teams (1v1, 5v1, 1v5) play out without errors and report correctly.
- A turn where nothing is legal except pass (everyone controlled, silenced, no target in reach) yields a pass, never an exception.
- A unit with no path to any enemy (the walled-off stall the throwaway bot hit) ends by round cap and is flagged `stalled`, never an endless loop.
- A mistyped character name in the CLI prints a clear error with close matches and exits 1.
- Taunt, puppeteer, revive and teleport reacts are obeyed or handled (a taunted unit only targets its taunter; a teleport react gets a destination).

## File Structure

- `js/rng.js` (new): seedable random source. `js/combat-logic.js` (modify): uses it; headless mode; extracted `handleTeleportClick`.
- `js/ai/snapshot.js`: `snapshot()`/`restore()` of `S`.
- `js/ai/apply.js`: turn-plan type, `applyPlan`, `settleReacts`.
- `js/ai/greedy.js`: the cheap policy (rollout policy and baseline opponent).
- `js/ai/candidates.js`: `enumeratePlans`, `enumerateReacts`.

- Tests in `tests/` named after the module.
